# Source Code vs Byte Code vs Binary Code

## Example File: `Chapter_01_JS_Basics/Helloworld.js`

```javascript
console.log("Hello World");
```

---

| Aspect | Source Code | Byte Code | Binary Code (Machine Code) |
|--------|-------------|-----------|----------------------------|
| **What it is** | Human-readable instructions written in a programming language | Intermediate, platform-independent representation of source code | Raw instructions executed directly by the CPU (0s and 1s) |
| **Readability** | Readable by humans (English-like syntax) | Somewhat readable by humans (mnemonic-like) | Not readable by humans without a disassembler |
| **Example (for our file)** | `console.log("Hello World");` | `get_property r0, console`<br>`push r0`<br>`load_string "Hello World"`<br>`call_method r0 "log"` | `10110000 00000001`<br>`01001000 01100101`<br>`01101100 01101100`<br>`01101111 ...` (hex `48 65 6C 6C 6F`) |
| **Who processes it** | Written by developers | Generated by compilers/interpreters (e.g. V8 engine generates Ignition bytecode) | Generated by assemblers or JIT compilers; executed by the CPU |
| **Language level** | High-level | Mid-level (between source and machine) | Low-level (machine language) |
| **Portability** | Portable across platforms (same JS runs on Windows, Linux, macOS) | Platform-independent within the same runtime (V8 bytecode is standard) | Not portable — tied to CPU architecture (x86, ARM, etc.) |
| **Tool used** | Text editor (VS Code, Notepad) | JavaScript engine (V8, SpiderMonkey) | CPU hardware |
| **Speed** | Slowest (must be interpreted/compiled first) | Faster than source, slower than binary | Fastest (directly executed by hardware) |
| **Storage size** | Very small (our file is ~30 bytes) | Medium (~few KB) | Larger (includes CPU instructions) |
| **Example in Node.js pipeline** | You write `console.log("Hello World");` in `.js` file | V8 parses & compiles it to Ignition bytecode at runtime | V8's TurboFan JIT may compile hot bytecode into native x86 machine code for speed |

---

## How It Flows (for `Helloworld.js`)

```
Source Code (.js)  ──parser──►  AST  ──Ignition──►  Byte Code  ──TurboFan JIT──►  Binary Code (x86)
     │                                                                                        │
     └──── Written by you              Generated at runtime by Node.js/V8              Executed by your CPU
```

- **Source code** is what you write and save in the file.
- When you run `node Helloworld.js`, V8 (Node.js's JS engine) parses it into an **Abstract Syntax Tree (AST)** and generates **Ignition bytecode** — an intermediate representation.
- Frequently executed ("hot") code gets further compiled by **TurboFan** into actual **binary machine code** that your CPU executes directly.
- For a one-liner like `console.log("Hello World");`, the entire script may stay as bytecode or get JIT-compiled depending on the engine's heuristics.
